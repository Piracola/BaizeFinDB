# M5 A 股 5 分钟资金主线雷达 MVP PRD

本文档修正下一阶段开发基线：M5 不是在 Telegram、报告、Web 三者里选一个入口先做，而是优先完成 **A 股 5 分钟资金主线雷达**。Telegram、Web、报告、持仓自选、日报周报和评分都围绕雷达闭环展开。

项目定位保持不变：BaizeFinDB 是个人 AI 金融雷达与投研辅助系统，不是自动交易系统，不输出买卖指令，不替用户做投资决策。

## 1. 当前背景

当前项目已完成 M4 轻量审查层闭环：

- Provider 能采集 AKShare 最小数据。
- Radar 能生成候选信号、P0/P1/P2 初判、生命周期和证据链。
- Governance 能审查信号并做分享预检。
- 公开分享 payload 已做脱源脱敏。

下一阶段的目标不是先铺入口，而是把雷达本身做成可日常使用、可审查、可推送、可报告、可复盘的最小闭环。

## 2. M5 北极星

M5 的真实 MVP：

```text
A 股 5 分钟资金主线雷达优先，入口和报告都消费雷达结果。
```

第一版只做 A 股资金主线雷达。美股后续只做财务、估值、基本面和事件分析，不做 5 分钟资金雷达。

核心问题：

- 当前 A 股市场是否出现资金主线？
- 资金主线来自哪个板块、主题或概念？
- 个股异动是否能反推到更大的板块/概念共振？
- 该信号是 P0、P1 还是 P2？
- 信号处在什么生命周期？
- 是否影响我的持仓或自选？
- 是否需要 Telegram 快速提醒、后台报告、日报周报或事后评分？

## 3. M5 范围

### 3.1 雷达扫描

- 每 5 分钟扫描一次 A 股市场。
- 同时观察板块、主题、概念和个股异动。
- 板块/主题/概念权重大于单票异动；单票异动优先用于反推相关板块、产业链、概念或风险事件。
- 雷达主数据按市场共享，不因个人持仓或自选改变主线等级。
- 持仓和自选只影响个人提醒优先级、展示排序和报告上下文。

### 3.2 P0/P1/P2 固定标准

P0/P1/P2 是系统固定标准，不能被入口、报告或 AI 临时改写。

| 等级 | 含义 | M5 判定口径 |
| --- | --- | --- |
| P0 | 强主线 / 重大风险 | 主线 P0 不能只由新闻触发，必须有资金、板块联动或市场情绪确认；风险 P0 可由重大公告、监管事件或黑天鹅单独触发。 |
| P1 | 疑似点火 / 值得观察 | 已有资金、情绪、板块联动或事件证据，但证据强度、持续性或一致性还不够 P0。默认 30 分钟内连续 3 次触发进入快报候选；阈值可通过环境变量调参。 |
| P2 | 弱信号 / 观察记录 | 单点异动、新闻待验证、联动不足、数据缺失或噪音概率较高，默认保留 7 天观察。 |

规则定级优先。AI 只负责解释、补证据、提示分歧和给出非交易建议等级，不能覆盖规则把信号改成 P0/P1/P2。

### 3.3 强度等级与生命周期分离

强度等级回答“当前重要性”，生命周期回答“主线阶段”。两者必须分开保存和展示。

- 强度等级：P0、P1、P2。
- 生命周期：点火、发酵、分歧、回流、高潮、退潮、熄火。
- 一个 P0 可以处于高潮或退潮阶段。
- 一个 P1 可以处于点火或回流阶段。
- 生命周期变化不能自动覆盖 P0/P1/P2，只能作为规则证据之一。

### 3.4 审查范围

Review Agent / Governance 只审查 M5 必要对象：

- P0 候选；
- P1 快报候选；
- risk 风险候选；
- holding/watchlist 相关候选；
- 所有即将发布的报告。

审查可以阻断、要求人工复核或允许发布，但不能替代规则引擎重新定级。所有报告发布前都必须审查。

### 3.5 Telegram 推送

Telegram 是雷达消费入口，不是独立产品线。

- P0：先发快速提醒，后台自动生成 standard report。
- P1：默认 30 分钟内连续 3 次触发，生成 quick report / 快报候选；阈值可通过环境变量调参。
- P2：不刷屏，保留 7 天观察，可在汇总里展示。
- 推送按 P0/P1/P2 折叠汇总，不按单条信号刷屏。
- blocked 不推送。
- needs_human_review 默认只推送给自己，并明确标注“需人工复核”。

M5 Telegram 命令只围绕雷达闭环：

| 命令 | 行为 |
| --- | --- |
| `/health` | 返回 API、DB、Redis 和扫描状态摘要 |
| `/radar` | 返回当前雷达总览和 P0/P1/P2 折叠摘要 |
| `/signals` | 返回最近信号列表 |
| `/signal <id>` | 返回单个信号摘要、证据摘要、生命周期和审查状态 |
| `/holding` | 返回持仓相关雷达影响 |
| `/watchlist` | 返回自选相关雷达影响 |
| `/reports` | 返回最近 quick/standard 报告 |

Telegram free-chat Agent 可以修改低风险个人数据，例如添加临时关注、备注或自选；高风险操作必须二次确认，例如删除关注、修改成本价/仓位比例、关闭提醒、触发 deep report、公开分享或导出含个人数据的报告。

### 3.6 Web MVP 页面

Web 是雷达查看和复盘入口，页面顺序固定为：

1. 雷达总览；
2. 信号详情；
3. 持仓/自选；
4. 报告列表。

M5 不做复杂大屏、报告编辑器、公开 SEO 页和多租户后台。页面只消费后端结果和发命令，不在前端重算雷达等级。

### 3.7 持仓和自选

MVP 必须支持手动维护持仓和自选。

持仓字段：

- 标的代码；
- 标的名称；
- 市场；
- 持仓备注；
- 成本价，可选；
- 仓位比例，可选；
- 是否启用提醒；
- 创建和更新时间。

持仓/自选规则：

- 只影响个人优先级、提醒排序、报告上下文和 Telegram/Web 展示。
- 不改变市场主线 P0/P1/P2。
- 按用户隔离，不能进入公开分享 payload。

### 3.8 报告体系

报告分三档：

| 类型 | 触发方式 | 用途 |
| --- | --- | --- |
| quick | 自动或手动 | 快速说明单个 P0/P1/risk/holding 相关信号。 |
| standard | P0 后台自动、用户手动 | 标准化主线报告，包含证据、分歧、风险和后续观察条件。 |
| deep | 仅手动 | 深度研究，M5 只预留，不自动触发。 |

自动生成最多到 quick / standard。deep 只能手动触发且需要二次确认。

报告建议等级固定为非交易口径：

- 重点关注；
- 继续观察；
- 谨慎跟踪；
- 暂不关注；
- 风险回避。

报告不得输出买入、卖出、满仓、稳赚、保证收益等诱导交易语言。

### 3.9 日报、周报和评分

MVP 包含基础日报、周报和事后评分。

- 日报：汇总当天 P0/P1/P2、持仓/自选影响、风险事件、报告产出和审查阻断。
- 周报：汇总一周主线延续、切换、退潮、风险和评分反馈。
- 评分窗口：1d、3d、5d、10d。
- 评分是综合评分，不只看涨跌幅；当前 v2 综合主线优先级、生命周期、审查状态、证据数量、连续触发、Provider 数据质量和信号时效性，后续真实行情反馈充足后再接后续走势校准。

### 3.10 分享页

- 分享页默认私密。
- 公开分享必须隐藏个人信息、持仓、自选、成本价、仓位比例、个人备注。
- 公开分享不展示原始来源、原始 URL、域名、大段原文、内部证据链、模型审计日志和原始审查字段。
- 内部仍保留完整证据链、审查记录和审计路径。

## 4. 后端责任边界

后端负责：

- 雷达计算；
- 定时调度；
- 状态记录；
- 报告触发；
- Provider 抽象；
- Agent / Review Agent 流程；
- DB、证据、审计和日志；
- Telegram/Web 命令落库和权限校验；
- 模型调用路由、fallback 和显式降级。

Web 和 Telegram 只消费结果和发命令，不能承担雷达等级计算、审查决策或报告发布判断。

MVP 使用 PostgreSQL + Redis。vector DB、pgvector、Qdrant、GraphRAG、Neo4j 后置，不能成为 M5 前置依赖。

## 5. 用户、权限和模型审计

- MVP 是单用户/白名单模式。
- 雷达主数据共享。
- 持仓、自选、报告、Telegram 会话、导出和分享按用户隔离。
- 高风险或高成本操作必须二次确认。
- 模型调用支持主模型和 fallback。
- 模型失败必须显式降级，不允许静默跳过或伪造 AI 结论。
- 模型审计日志默认不保存完整 raw prompt；只有 debug 模式才保存完整上下文。

## 6. 验收标准

M5 完成时至少满足：

- [x] 能按 5 分钟节奏运行 A 股雷达扫描。
- [x] 雷达总览能展示 P0/P1/P2 折叠摘要、板块/概念主线和个股回推证据。
- [x] 主线 P0 不会只由新闻触发，必须有资金、板块或情绪确认。
- [x] 风险 P0 可由重大公告、监管或黑天鹅单独触发。
- [x] P1 连续触发能进入 quick report / 快报候选。
- [x] P2 默认保留 7 天观察。
- [x] 强度等级和生命周期分开保存、分开展示。
- [x] Review Agent 只审查 P0/P1/risk/holding 相关候选和发布前报告。
- [x] P0 Telegram 快速提醒后能触发后台 standard report。
- [x] Telegram 推送按 P0/P1/P2 折叠汇总。
- [x] 支持手动持仓和自选，成本价和仓位比例可为空。
- [x] 持仓/自选只影响个人优先级，不改变市场主线等级。
- [x] Web 页面按雷达总览、信号详情、持仓/自选、报告列表顺序可用。
- [x] quick/standard/deep 报告类型明确，deep 只能手动触发。
- [x] 日报、周报和 1d/3d/5d/10d 基础评分可生成。
- [x] 公开分享不泄露个人数据和原始来源。
- [x] 模型失败有显式降级记录，审计默认不保存完整 raw prompt。
- [x] 测试覆盖 P0/P1/P2 规则、生命周期、审查阻断、推送折叠、持仓隔离、报告审查和分享脱敏。

## 7. 明确不做

- 不做自动交易、自动下单、券商接入。
- 不输出强买卖建议、保证收益或仓位指令。
- 不做美股 5 分钟资金雷达。
- 不做复杂多租户 SaaS。
- 不做完整 Web 大屏或运营后台。
- 不做完整研报库、产业链知识图谱、历史回测系统。
- 不把 vector DB、pgvector、Qdrant、GraphRAG、Neo4j 放进 M5 依赖。

## 8. 下一步执行顺序

1. 巩固后端雷达规则：板块/概念权重、个股回推、P0/P1/P2 和生命周期。
2. 补用户、持仓、自选、报告、推送和评分所需的最小数据模型。
3. 接调度和状态记录，保证 5 分钟扫描可追踪、可失败、可恢复。
4. 接 P0/P1/risk/holding 审查和报告发布前审查。
5. 接 Telegram 折叠推送和命令查询。
6. 接 quick/standard 报告生成，deep 只预留手动入口。
7. 接 Web 四个 MVP 页面。
8. 接日报、周报、基础评分和调参反馈。
